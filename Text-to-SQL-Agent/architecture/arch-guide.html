System Architecture
Four layers connected by LangChain acting as the central coordinator.
Component Responsibilities
What each piece owns, and what it hands off.
🖥️
Streamlit
UI Layer

The web framework that builds the chat interface. It handles all rendering and state — no HTML or CSS needed. Your app.py is almost entirely Streamlit calls.

  • Renders the chat history from st.session_state
  • Captures user input via st.chat_input()
  • Shows a spinner while the agent is thinking
  • Reads the API key from secrets.toml or env
  • Passes the question to LangChain, displays the answer
🔗
LangChain
Orchestration Layer

The coordinator. create_sql_agent knows the DB schema and decides when to ask OpenAI for SQL and when to execute it. It runs the agentic loop so you don't have to.

  • Inspects the SQLite schema on startup
  • Builds prompts: schema + user question → OpenAI
  • Executes the generated SQL against SQLite
  • Sends results back to OpenAI for formatting
  • Returns the final answer to Streamlit
🤖
OpenAI GPT-4o-mini
Intelligence Layer

The language model that understands Hebrew/English and generates SQL. It's called twice per question: once to produce the query, once to turn raw results into a readable answer.

  • Input 1: schema + question → Output: SQL query
  • Input 2: SQL results + context → Output: human answer
  • temperature=0 makes SQL generation deterministic
  • Runs remotely — no local compute, billed per token
🗄️
SQLite + SQLAlchemy
Data Layer

A serverless, file-based database. The entire DB is credit_risk.db — one file, no installation. SQLAlchemy is the Python connector that LangChain uses to talk to it.

  • Stores the loans table (100 mock records)
  • Executes SQL sent by LangChain
  • Returns raw result sets
  • Exposes schema metadata for LangChain to describe to OpenAI
☁️
Streamlit Cloud
Hosting & Deployment

The free hosting platform that runs the app publicly. It watches your GitHub repo and redeploys automatically on every push to main. Secrets never touch the filesystem — they live in its dashboard.

  • Watches GitHub → auto-redeploys on push to main
  • Runs pip install -r requirements.txt on each deploy
  • Injects OPENAI_API_KEY from the Secrets dashboard into st.secrets
  • Provides a public URL — no servers to manage
  • Free tier handles small portfolio projects without any cost
